# 生产化路线图

这份路线图用于说明当前作品集版本和真实企业生产环境之间的差距。当前项目优先保证本地可运行、链路完整、便于面试演示；生产化时应围绕检索质量、数据可靠性、权限安全、Agent 稳定性、观测与成本治理逐步升级。

## 当前定位

| 维度 | 当前版本 | 适合场景 |
| --- | --- | --- |
| 检索 | BM25 + 可选 Embedding + 融合重排 | 中小规模知识库、离线或联网演示 |
| 数据库 | SQLite | 单机原型、小规模样例数据 |
| 回答生成 | 本地抽取式回答，可选 OpenAI 兼容接口 | 离线演示、低成本调试 |
| Agent | 受控规划、超时重试、同步执行 | 展示规划、工具调用、权限控制和失败治理 |
| 权限 | 管理员、技术员工、普通员工 | 角色级演示 |
| 观测 | token 估算、成本估算、决策轨迹、Agent 运行指标 | 面试展示和本地排查 |

## 阶段一：检索质量升级

当前已经完成本地混合检索闭环，下一步把存储和重排升级到生产级组件。

- 已支持通过 OpenAI 兼容接口为知识片段批量生成向量，并为历史文档补建索引。
- 使用 PostgreSQL + pgvector 保存向量，避免额外维护独立向量数据库。
- 已使用 BM25 作为关键词召回通道，并与向量分数融合。
- 当前使用标题和词项覆盖做本地重排，下一步接入独立 rerank 模型。
- 检索调试页已展示 BM25、Vector、Rerank 和最终分数。

价值：

- 提升同义表达、长问题和跨文档问题的召回质量。
- 保留关键词检索的可解释性，同时增加语义召回能力。
- 面试时可以展示混合检索已落地，并说明为什么下一步迁移 pgvector 和独立 rerank。

## 阶段二：数据与部署升级

目标是让系统从本地原型变成可部署服务。

- 将 SQLite 迁移到 PostgreSQL。
- 引入数据库迁移工具，管理 schema 变更。
- 上传文件改为对象存储或受控文件服务。
- 区分本地、测试、生产环境配置。
- 使用 GitHub Actions 运行测试，发布前自动执行 `python -m pytest`。
- 生产环境使用 HTTPS、反向代理和进程守护。

价值：

- 支持多人使用和更可靠的数据持久化。
- 让数据库变更可追踪，避免手工改表。
- 让 GitHub 仓库具备基础 CI 可信度。

## 阶段三：异步 Agent 与任务治理

目标是把同步 Agent 原型升级为稳定可控的任务系统。

- 将大文件解析、索引重建、批量评测和 Agent 执行放入异步队列。
- Agent 工具调用已增加超时、重试和失败状态，下一步补充幂等 key 与取消能力。
- 高风险工具加入人工审批节点，例如创建知识缺口、查询审计日志、批量重建索引。
- 保存 Agent 每一步的输入、输出、耗时、错误和操作者。
- 增加任务列表和失败重试入口。

价值：

- 避免长任务阻塞接口请求。
- 降低 Agent 工具误操作风险。
- 让 Agent 从“演示工具调用”升级为“可治理的业务自动化”。

## 阶段四：权限与安全升级

目标是适配真实企业内部知识权限。

- 从角色权限扩展到部门级 ACL、岗位级 ACL 和文档级授权。
- 文档密级从 public/internal/sensitive 扩展为可配置策略。
- 增加审计日志留存策略和导出策略。
- 增加访问频率限制、异常访问告警和敏感问题复核。
- 接入企业 SSO 或 OAuth/OIDC，替代本地演示账号。
- 对密钥、连接串和敏感配置使用托管 secrets。

价值：

- 避免普通员工越权访问敏感资料。
- 支持不同部门看到不同知识范围。
- 满足企业知识库常见的合规和审计要求。

## 阶段五：观测与成本治理

目标是让 AI 应用可度量、可排查、可控成本。

- 将当前 token 估算升级为真实模型用量记录。
- 记录每次 LLM 请求的模型、延迟、输入 token、输出 token、费用和错误。
- 将 QA 决策轨迹和 Agent 工具调用接入集中日志或 tracing。
- 建立按用户、部门、文档、模型维度的成本看板。
- 对高成本问题、低置信回答、重复失败工具调用进行告警。

价值：

- 面向业务方解释 AI 成本和使用效果。
- 快速定位回答质量下降、模型失败或检索召回异常。
- 让 AI 应用具备持续运营能力，而不是只停留在功能演示。

## 建议实施顺序

1. 先加 CI、发布检查和测试基线，保证每次改动可回归。
2. 再升级 PostgreSQL + pgvector，解决数据和语义检索基础。
3. 然后加入 rerank 和检索评测集，验证质量提升。
4. 再做异步 Agent 和任务状态，解决稳定性问题。
5. 最后扩展部门级 ACL、SSO、审计留存和成本看板。

## 面试回答模板

如果面试官问“这个项目距离生产还有什么差距”，可以这样回答：

> 当前版本已经实现 BM25 + 可选 Embedding 混合检索、本地重排、Recall@K/MRR 评测，以及受控 Agent 规划、超时重试和失败状态。为了保持一键运行，向量和业务数据仍在 SQLite，Agent 仍同步等待。生产化时会把数据库迁移到 PostgreSQL + pgvector，接入独立 rerank，把 Agent、大文件解析和批量评测放入异步队列，并补充部门级 ACL、SSO、集中 tracing 和成本治理。
