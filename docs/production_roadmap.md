# 生产化路线图

这份路线图用于说明当前作品集版本和真实企业生产环境之间的差距。当前项目优先保证本地可运行、链路完整、便于面试演示；生产化时应围绕检索质量、数据可靠性、权限安全、Agent 稳定性、观测与成本治理逐步升级。

## 当前定位

| 维度 | 当前版本 | 适合场景 |
| --- | --- | --- |
| 检索 | FTS5 有界候选 + 字段加权 BM25 + 可选 Embedding/pgvector + 融合重排 | 中小规模知识库、离线或联网演示 |
| 数据库 | SQLite | 单机原型、小规模样例数据 |
| 回答生成 | 本地抽取式回答，可选 OpenAI 兼容接口；统一重试、退避、熔断和降级 | 离线演示、联网调用和供应商短暂故障 |
| Agent | 受控规划、进程内异步任务、幂等提交、取消重试 | 展示规划、工具调用、任务状态和失败治理 |
| 权限 | 管理员、技术员工、普通员工 | 角色级演示 |
| 观测 | token/成本、模型尝试次数与延迟、错误分类、决策轨迹、Agent 运行指标 | 面试展示和本地排查 |
| 部署 | 非 root 单 Worker 容器、持久卷、强密码引导、数据库就绪检查 | 单机演示、小规模内部试用 |

## 阶段一：检索质量升级

当前已经完成本地混合检索闭环，并提供可选 pgvector 检索投影；下一步继续升级关键词检索和重排组件。

- 已支持通过 OpenAI 兼容接口为知识片段批量生成向量，并为历史文档补建索引。
- 已支持使用 PostgreSQL + pgvector HNSW 保存和检索向量，并通过连接池、历史对账、实时允许 ID 过滤和透明降级控制运行风险。
- 已使用正文 70%、标题 30% 的字段加权 BM25 作为关键词召回通道，并与向量分数融合。
- 已使用自动同步的 SQLite FTS5 生成有界关键词候选，避免正常关键词路径把全部可访问片段加载到 Python。
- 当前使用标题和词项覆盖做本地重排，下一步接入独立 rerank 模型。
- 检索调试页已展示 BM25、Vector、Rerank 和最终分数。
- 已建立版本化黄金数据集、数据集指纹、批准/历史基线回退检测和 CI 失败门禁。

价值：

- 提升同义表达、长问题和跨文档问题的召回质量。
- 保留关键词检索的可解释性，同时增加语义召回能力。
- 面试时可以展示 SQLite 零服务模式与 pgvector 实际检索模式，并说明为什么下一步迁移关键词通道和独立 rerank。
- 每次调整检索权重、切分或拒答规则时，都能用同一套黄金集证明没有退化。

## 阶段二：数据与部署升级

目标是让系统从本地原型变成可部署服务。

- 将 SQLite 迁移到 PostgreSQL。
- 已引入 SQLite 版本化迁移、历史 SHA-256 校验、逐版本事务、并发启动锁、在线备份与 readiness 版本检查；迁移 PostgreSQL 时再切换到 Alembic。
- 上传文件改为对象存储或受控文件服务。
- 区分本地、测试、生产环境配置。
- 使用 GitHub Actions 运行测试，发布前自动执行 `python -m pytest`。
- 已提供非 root Docker 镜像、Compose 安全默认项、持久卷和数据库就绪检查。
- CI 已验证生产空密码拒绝、容器管理员登录、非 root 用户和持久化重启。
- 生产环境使用 HTTPS、反向代理和进程守护。

价值：

- 支持多人使用和更可靠的数据持久化。
- 让数据库变更可追踪，避免手工改表。
- 让 GitHub 仓库具备基础 CI 可信度。

## 阶段三：异步 Agent 与任务治理

当前已经完成单实例可用的异步任务闭环，下一步升级为支持多实例和进程故障恢复的外部任务系统。

- Agent 请求已通过有界进程内执行器异步运行，API 立即返回任务编号。
- 已持久化 queued、running、cancel_requested、cancelled、completed 和 failed 状态。
- 已支持用户级幂等 key、活动任务上限、协作式取消和失败任务重试。
- 下一步将 Agent、大文件解析、索引重建和批量评测统一迁移到 Redis/Celery 等外部队列。
- 增加任务租约、心跳、跨实例接管和死信队列，解决进程退出后的可靠恢复。
- 高风险工具加入人工审批节点，例如创建知识缺口、查询审计日志、批量重建索引。
- 保存 Agent 每一步的输入、输出、耗时、错误和操作者。
- 当前取消发生在工具步骤之间；生产环境需要供应商级请求取消和更细粒度的可中断工具。

价值：

- 避免长任务阻塞接口请求。
- 降低 Agent 工具误操作风险。
- 让 Agent 从“演示工具调用”升级为“可治理的业务自动化”。

## 阶段四：权限与安全升级

目标是适配真实企业内部知识权限。

- 从角色权限扩展到部门级 ACL、岗位级 ACL 和文档级授权。
- 文档密级从 public/internal/sensitive 扩展为可配置策略。
- 增加审计日志留存策略和导出策略。
- 增加访问频率限制、异常访问告警和敏感问题复核。
- 接入企业 SSO 或 OAuth/OIDC，替代本地演示账号。
- 对密钥、连接串和敏感配置使用托管 secrets。

价值：

- 避免普通员工越权访问敏感资料。
- 支持不同部门看到不同知识范围。
- 满足企业知识库常见的合规和审计要求。

## 阶段五：观测与成本治理

目标是让 AI 应用可度量、可排查、可控成本。

- 已在供应商返回 usage 时记录真实 token，离线与降级路径明确标记为本地估算。
- 已记录每次问答模型请求的模型、尝试次数、总延迟、HTTP 状态、错误分类、输入 token、输出 token 和估算费用，并持久化到问答日志。
- 已统一问答、Embedding 和 Agent Planner 的可恢复故障重试、指数退避、`Retry-After`、响应上限与进程内熔断。
- 将 QA 决策轨迹和 Agent 工具调用接入集中日志或 tracing。
- 建立按用户、部门、文档、模型维度的成本看板。
- 对高成本问题、低置信回答、重复失败工具调用进行告警。

价值：

- 面向业务方解释 AI 成本和使用效果。
- 快速定位回答质量下降、模型失败或检索召回异常。
- 让 AI 应用具备持续运营能力，而不是只停留在功能演示。

## 建议实施顺序

1. 先加 CI、发布检查和测试基线，保证每次改动可回归。
2. 已先把向量通道升级为可选 PostgreSQL + pgvector；下一步迁移业务表和关键词检索，解决多实例与大语料扩展。
3. 扩展当前黄金集的业务覆盖与难例规模，再接入独立 rerank 并用门禁验证真实增益。
4. 将进程内异步 Agent 升级为外部队列和人工审批，解决多实例可靠性问题。
5. 最后扩展部门级 ACL、SSO、审计留存和成本看板。

## 面试回答模板

如果面试官问“这个项目距离生产还有什么差距”，可以这样回答：

> 当前版本已经实现 FTS5 有界关键词候选、字段加权 BM25 + 可选 Embedding 混合检索、本地重排，以及基于版本化黄金集、绝对阈值和批准基线的 CI 质量门禁；向量通道可切换到带 HNSW、连接池、实时文档权限过滤和真实 CI 集成测试的 pgvector。问答、Embedding 和 Agent Planner 统一通过有界重试、指数退避、错误分类和进程内熔断调用模型，问答与 Planner 都有确定性降级；Agent 还具备受控规划、进程内异步执行、幂等、取消和失败重试。为了保持一键运行，业务事实源和默认向量副本仍在 SQLite，字段加权 BM25 仍在候选小集合上由应用计算，任务执行器和模型熔断状态也仍是单实例进程内组件。生产化时会扩大分领域评测集，继续迁移业务表、统一检索后端和外部任务队列，接入独立 rerank、任务租约与人工审批，并补充部门级 ACL、SSO、集中 tracing、共享模型网关和成本治理。
