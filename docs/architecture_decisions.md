本文档记录“企业知识库 RAG + AI Agent 平台”的关键技术取舍，帮助面试官理解当前实现为什么这样设计，以及后续如何生产化升级。

## ADR-001：使用 FastAPI 作为后端框架

**决策：** 后端使用 FastAPI 承载认证、文档、问答、Agent、评测、审计和 dashboard 接口。

**原因：**

- Python 生态适合 AI 应用开发。
- FastAPI 对 Pydantic、OpenAPI 和异步接口支持较好。
- 面试中容易展示接口设计、依赖注入、测试和后续模型接入。

**取舍：** 当前项目更重视 AI 应用闭环和本地可运行性，没有引入复杂微服务拆分。生产环境可以按业务边界拆分文档处理、检索、Agent 执行和评测任务。

## ADR-002：使用 SQLite 支撑本地演示

**决策：** 当前版本使用 SQLite 存储用户、文档、片段、问答日志、Agent 运行和评测记录。

**原因：**

- 零外部依赖，适合 GitHub 作品集、毕业设计演示和面试快速复现。
- 一键启动成本低，不需要先安装 PostgreSQL 或 Redis。
- 表结构仍能体现企业知识库系统的基本数据建模能力。

**取舍：** SQLite 不适合作为多人生产环境数据库。生产化路径是迁移到 PostgreSQL，并配合迁移工具、连接池、备份和权限策略。

## ADR-003：使用可降级的混合检索

**决策：** 默认使用字段加权 BM25 + 本地重排，其中正文占 70%、标题占 30%；显式配置 Embedding 后，文档入库会持久化向量，查询时融合 BM25 和向量相似度。历史文档支持批量补建向量。

**原因：**

- 未配置外部服务时仍可离线运行，不依赖 Embedding API。
- 字段加权 BM25、向量和重排分数分别保留，便于排查召回和排序问题。
- Embedding 模型必须显式配置，不硬编码会过期的模型名称。

**取舍：** 当前向量存储在 SQLite JSON 字段中，适合中小规模演示语料。生产化应迁移到 pgvector 或专用向量库，并使用独立 rerank 模型。

## ADR-004：Agent 工具调用使用可控工具链

**决策：** Agent 可以使用确定性规划，也可以启用模型规划，但计划只能从安全检查、知识库检索、答案生成、知识缺口创建和日志查询白名单中选择。

**原因：**

- 企业 AI 应用需要可审计、可解释、可权限控制。
- 每一步工具调用都有输入、输出、重试次数、耗时、状态和时间线，方便排查。
- 更适合面试展示“Agent 工程化”，而不是只展示不可控的模型输出。

**取舍：** 当前已支持进程内异步执行、持久化状态、幂等提交、协作式取消和失败重试，适合单实例演示与小规模部署。生产化仍需外部任务队列、任务租约、跨实例恢复、人工审批和更细粒度 ACL。

## ADR-005：保留本地抽取式回答与 OpenAI Chat Completions 兼容配置

**决策：** 默认未配置 API Key 时使用本地抽取式回答；配置环境变量后可接入 OpenAI Chat Completions 兼容接口。

回答生成前增加关键条件覆盖检查。系统从问题中提取关键短语，计算它们在 Top-K 标题和片段中的覆盖率；低于 `RAG_MIN_EVIDENCE_COVERAGE` 时不进入模型或本地拼接，而是返回可解释拒答，并记录覆盖率与缺失词。

**原因：**

- 面试演示不依赖外部网络和付费 Key。
- 简历项目可以稳定复现，不会因为模型服务不可用而无法演示。
- 仍保留真实大模型接入路径，体现 AI 应用扩展能力。

**取舍：** 本地抽取式回答能力有限，适合演示可信问答链路。真实生产效果需要接入更强模型、提示词模板、结构化输出和调用成本治理。

## ADR-006：发布治理作为工程能力的一部分

**决策：** 仓库包含 `.gitignore`、GitHub Actions、发布清单、最终验收报告、发布检查脚本、简历项目卡和面试官评分卡。

**原因：**

- GitHub 作品集不只看功能，还看可复现、可维护和边界意识。
- 发布检查脚本可以避免本地数据库、上传文件、Word 文档、隧道工具和密钥进入公开仓库。
- CI 和测试能证明项目不是“只在本机跑过一次”。

**取舍：** 这些治理文档不直接增加业务功能，但会显著提高项目在面试官眼中的工程可信度。

## ADR-007：默认安全与可解释降级

**决策：** 会话默认 12 小时过期，上传文件默认限制 10 MB，同源部署默认不开放 CORS；模型调用结果显式区分大模型生成、本地抽取和失败后的本地降级。

**原因：**

- 会话永不过期、无限制上传和通配跨域都会扩大演示系统暴露后的风险。
- 模型不可用时保留离线演示能力，但不能把本地回答和估算 Token 误报为供应商调用结果。
- 统一记录 `generation_mode`、`token_source` 和 `fallback_reason`，便于排障和成本分析。

**取舍：** 当前仍是轻量本地认证和文件校验。生产环境应继续增加 SSO、对象存储、恶意文件扫描、速率限制、模型网关和集中式可观测平台。

## ADR-008：使用版本化黄金数据集作为 RAG 回归门禁

**决策：** 将黄金用例和批准基线保存为仓库内 JSON，使用稳定键、版本号和 SHA-256 指纹识别数据集；每条用例声明执行角色，评测同时检查 Recall@K、MRR、答案、拒答、访问控制准确率的绝对阈值，以及相对同指纹、同 Top K 基线的最大回退。应用优先采用兼容的历史通过运行，首次运行回退到批准基线；CI 固定读取批准基线。CLI 与 API 共用门禁策略，CLI 失败返回非零退出码并在 GitHub Actions 上传 JSON 报告。

**原因：**

- 普通单元测试只能证明代码按预期执行，不能证明检索或拒答调整没有降低 AI 质量。
- 只在页面展示分数不会阻止退化进入主分支，门禁必须影响 CI 退出状态。
- 数据集指纹可以避免拿不同用例、不同 Top K 的结果进行无效比较。

**取舍：** 当前黄金集规模较小，适合仓库级确定性回归。生产环境仍需要分领域扩容、人工标注一致性和模型/Prompt 版本维度。
