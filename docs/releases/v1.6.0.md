# v1.6.0 - Resilient Model Gateway Release

`v1.6.0` 解决问答生成、Embedding 和 Agent Planner 各自直接请求模型供应商、只有固定超时且错误语义不一致的问题。三条链路现在共用模型韧性网关，在不增加外部服务依赖的前提下提供有界重试、指数退避、熔断、错误分类和调用诊断。

## 核心变化

- 只对网络错误、超时、HTTP 429 和可恢复 5xx 重试；401、403、请求错误和非法响应立即失败。
- 支持受上限约束的 `Retry-After` 与指数退避，最大尝试次数、超时、退避和响应体均有硬限制。
- 连续可恢复故障按供应商主机打开进程内熔断，冷却后只允许一个半开探测请求。
- 问答失败回退带引用的本地抽取，Agent Planner 回退确定性白名单计划，Embedding 失败不写入部分批次向量。
- 问答日志、决策轨迹和页面记录供应商尝试次数、总延迟、HTTP 状态与错误分类。
- 文档上传、向量重建和重索引响应返回 Embedding 网关诊断。
- `/api/health/ready` 返回不含供应商 URL 和密钥的模型网关聚合状态；模型是可选增强，熔断不会让可降级应用错误地变为不可就绪。

## 故障行为

| 故障 | 网关行为 | 业务结果 |
| --- | --- | --- |
| 超时、网络错误、5xx | 有界重试，连续失败后熔断 | 问答本地降级，Planner 确定性降级 |
| HTTP 429 | 尊重有界 `Retry-After` 后重试 | 成功则继续，失败则透明降级 |
| HTTP 401/403 | 不重试 | 返回 `provider_auth_error` 并降级 |
| 非法或超大响应 | 不重试 | 返回 `invalid_provider_response` |
| 熔断已打开 | 不发送网络请求 | 返回 `provider_circuit_open` |

## 验证证据

- 本地全量回归：161 项 pytest 通过，2 项 PostgreSQL 专用测试按设计跳过。
- 模型网关故障注入：9 项测试覆盖 429、`Retry-After`、超时、401、连续 503、熔断拒绝、半开恢复、响应上限和三条调用链诊断。
- RAG 质量门禁：12/12 用例通过，Recall@K、MRR、答案、拒答、访问控制准确率均为 100%。
- 发布检查：必需文件、忽略规则、Markdown 链接和疑似密钥扫描通过。
- 真实启动：隔离数据库实例的 SQLite、FTS5、向量后端和模型未配置降级状态均正常。

## 诚实边界

当前熔断器和指标是单进程内存状态，匹配项目的非 root 单 Worker 交付，不等于跨实例高可用模型网关。生产多实例应使用独立模型代理或 API Gateway，并接入集中 tracing、告警、预算、密钥托管和多供应商路由。
