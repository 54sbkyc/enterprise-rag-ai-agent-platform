# v1.4.0 - Pgvector Retrieval Infrastructure Release

`v1.4.0` 把语义向量通道从“SQLite JSON + Python 全量余弦扫描”升级为可选的 PostgreSQL + pgvector HNSW 检索，同时保留仓库克隆后零外部服务运行的默认体验。本版本没有增加展示页面，重点解决真实检索扩展、权限一致性、故障可见性和可复现验证。

## 核心变化

- 使用 pgvector 余弦距离 HNSW 索引执行向量 Top-K，并启用 filtered iterative scan。
- 使用有界 Psycopg 连接池复用数据库连接，支持连接超时和池大小配置。
- 文档上传、Embedding 重建、重索引和删除自动同步外部向量投影。
- 管理员可调用 `/api/documents/vector-store/sync` 对账历史 SQLite 向量，不重复消耗模型调用。
- pgvector 查询只接收 SQLite 实时计算出的允许片段 ID，文档密级变化和孤儿向量不能绕过权限边界。
- 搜索解释、引用和 Agent 结果显式标记 `vector_backend` 与 `vector_degraded`。
- 可选择 pgvector 故障后回退 SQLite JSON，或让就绪检查返回 `503` 阻止流量进入。

## 交付与验证

- 新增 `compose.pgvector.yaml`，使用 `pgvector/pgvector:0.8.2-pg17-bookworm`、健康检查和独立数据卷。
- 运行依赖锁定为 `pgvector 0.5.0`、`psycopg 3.3.4` 和 `psycopg-pool 3.3.1`。
- 143 项 pytest 自动化测试通过，另有 2 项真实 pgvector PostgreSQL 集成测试通过。
- 12 条 `enterprise-rag-golden-v2` 用例全部通过，Recall@K、MRR、答案、拒答与访问控制准确率均为 100%。
- GitHub Actions 的 pytest、pgvector integration 和加固容器烟测三个 Job 全部通过。

配置、对账、故障行为和维度迁移见 [pgvector 检索后端](../pgvector_retrieval.md)。架构取舍见 [ADR-010](../architecture_decisions.md)。

## 诚实边界

- 这是向量检索后端升级，不是完整 PostgreSQL 业务数据库迁移。
- SQLite 仍是用户、文档、日志、Agent 与评测的事实源，pgvector 是可重建投影。
- BM25 仍在应用进程中计算；更大规模需要继续迁移业务表、全文检索和任务队列。
- SQLite 与 PostgreSQL 无共享事务，当前采用最终一致与显式对账，不宣称跨库强一致。
