# v1.3.0 - Secure Container Deployment Release

`v1.3.0` 把项目从“可以在开发机启动”推进为“可以在干净 Docker 环境中用安全默认项复现并验收”。本版本没有继续增加页面，而是解决部署身份、弱默认口令、数据持久化、真实就绪检查和 CI 容器实跑这些交付问题。

## 核心变化

- **非 root 运行镜像**：Python 3.12 镜像使用 UID `10001`，只安装精简运行依赖，固定一个 Uvicorn Worker。
- **Compose 安全默认项**：默认仅绑定 `127.0.0.1`，根文件系统只读，使用独立 `/tmp`、能力裁剪和 `no-new-privileges`。
- **生产账号引导**：生产空库必须配置至少 12 位管理员密码，只创建管理员，不创建公开演示账号；重启不会覆盖已有密码。
- **数据持久化**：SQLite 与上传目录统一写入命名卷，普通 `docker compose down` 不删除业务数据。
- **真实健康检查**：liveness 只证明进程存活，readiness 会执行 SQLite 查询；异常返回通用 `503`，不泄露内部路径。
- **容器 CI 实跑**：GitHub Actions 从仓库构建镜像，验证无密码拒绝、非 root 身份、数据库就绪、管理员登录和持久卷重启。

## 验证结果

- 136 项 pytest 自动化测试全部通过。
- `enterprise-rag-golden-v2` 的 12 条角色化用例全部通过。
- Recall@K `100%`、MRR `1.0000`、答案正确率 `100%`、拒答准确率 `100%`、访问控制准确率 `100%`。
- GitHub Actions 的 `container-smoke` 在干净 Ubuntu Runner 成功完成镜像构建和容器端到端验收。
- Compose 配置解析、锁定依赖、`pip check`、Python 编译、Markdown 链接、忽略规则和疑似密钥扫描通过。

## 快速部署

```powershell
Copy-Item .env.example .env
```

在 `.env` 中配置 `RAG_BOOTSTRAP_ADMIN_PASSWORD` 后运行：

```powershell
docker compose config
docker compose up --build -d
Invoke-RestMethod http://127.0.0.1:8000/api/health/ready
```

完整操作见 [Docker 安全部署](../container_deployment.md)。

## 生产边界

- 当前容器仍是 SQLite、文件卷和进程内 Agent 的单实例实现，不能通过增加 Worker 或副本直接横向扩容。
- 公网环境仍需要 HTTPS 反向代理、SSO/OIDC、速率限制、恶意文件扫描、集中日志、密钥托管和恢复演练。
- 多实例部署前应迁移 PostgreSQL + pgvector、对象存储、外部任务队列和独立 rerank。

架构取舍与后续演进见 [架构决策记录](../architecture_decisions.md) 和 [生产化路线图](../production_roadmap.md)。
