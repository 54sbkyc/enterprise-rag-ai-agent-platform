# v1.5.0 - FTS5 Bounded Hybrid Retrieval Release

`v1.5.0` 解决正常关键词检索随语料规模增长而把全部可访问片段加载到 Python 的问题，并把 pgvector 权限过滤从全量片段 ID 改为实时文档 ID。系统现在先由 SQLite FTS5 和 pgvector HNSW 分别返回有限候选，再回载小集合执行字段加权 BM25、向量融合、本地重排和实时权限复核。

## 主要变化

- 新增自动同步的 `chunk_fts` 索引，复用 jieba 与单字回退分词，覆盖片段新增、正文修改、删除和文档标题更新。
- FTS 查询对用户输入先分词、去重、限制词数并转义，不直接执行用户提供的 MATCH 运算符。
- 新增 `RAG_LEXICAL_CANDIDATE_LIMIT` 与 `RAG_VECTOR_CANDIDATE_LIMIT`，并设置代码侧硬上限。
- pgvector 使用当前可访问 `document_id` 过滤 HNSW 候选；候选必须关联回当前 SQLite 片段才能进入答案链路。
- 搜索解释与就绪检查新增关键词后端、降级原因、候选数和语料总数，FTS 表或同步触发器异常时显式回退全量 BM25。
- 组件图、架构决策、部署配置、面试话术和生产化边界同步到当前实现。

## 验证结果

- 本地总验收：152 项 pytest 通过，2 项 PostgreSQL 专用测试按设计跳过。
- GitHub Actions：152 项 pytest、2 项真实 pgvector PostgreSQL 集成测试和加固容器烟测全部通过。
- 12 条 `enterprise-rag-golden-v2` 用例全部通过。
- Recall@K 100%、MRR 1.0、答案准确率 100%、拒答准确率 100%、访问控制准确率 100%。
- 规模回归用例在 80 个匹配片段下只回载配置的 25 个关键词候选。

## 诚实边界

- 默认 SQLite JSON 向量模式与 pgvector 故障后的本地向量降级仍会扫描可访问向量；正常 pgvector 模式才使用有界 HNSW 候选。
- FTS5 不可用时系统优先保证正确性，显式降级到原有全量 BM25。
- 业务事实源仍是单实例 SQLite；大规模多实例生产部署需要继续迁移统一数据库、对象存储和外部任务队列。

实现与运维细节见 [SQLite FTS5 关键词检索](../fts5_retrieval.md)、[pgvector 检索后端](../pgvector_retrieval.md) 和 [架构决策](../architecture_decisions.md)。
