# RAG 质量门禁

项目使用版本化黄金数据集和确定性离线执行器，在代码提交阶段检查检索与回答质量。门禁和评测中心共用同一套指标、阈值和执行逻辑。

## 运行方式

从项目根目录运行完整验收：

```powershell
.\scripts\verify_project.ps1
```

只运行 RAG 门禁：

```powershell
cd backend
python -m app.eval_gate_cli --output ..\.runtime\evaluation-gate-report.json
```

命令使用临时数据库导入企业样例资料，不修改开发数据库。默认关闭外部 LLM 和 Embedding，保证本地与 CI 结果可复现。门禁失败时进程返回非零退出码。

## 黄金数据集

数据集位于 `backend/evaluation/golden_cases.v1.json`，批准基线位于 `backend/evaluation/approved_baseline.v1.json`。每条用例包含：

- 稳定的 `key` 和业务分类；
- 问题、期望关键词与期望来源；
- 是否应该回答，用于验证无依据问题的拒答行为。

应用启动时会将黄金数据集同步到数据库。黄金用例在 API 和界面中只读；临时实验可以新增自定义用例，不会改变版本化基线。

修改黄金问题、期望结果或用例集合时，需要升级数据集版本。系统会根据规范化内容计算 SHA-256 指纹，只有数据集指纹与 Top K 相同的历史运行才能作为应用内自动基线。

CI 不依赖临时数据库中的历史记录，而是读取随代码提交的批准基线。数据集版本、指纹或 Top K 不一致时直接失败；确需实验新数据集或 Top K 时，可显式使用 `--no-baseline` 只运行绝对阈值，确认结果后再通过代码评审更新批准基线。

## 默认策略

| 检查 | 默认要求 |
| --- | --- |
| 用例数 | 至少 5 条 |
| Recall@K | 不低于 80% |
| MRR | 不低于 75% |
| 答案正确率 | 不低于 80% |
| 拒答准确率 | 不低于 80% |
| 相对基线回退 | 单项不超过 5 个百分点 |

阈值检查可以防止绝对质量过低，基线比较可以发现一次改动造成的相对退化。应用优先采用同指纹、同 Top K 的最近历史通过运行；没有历史运行时使用批准基线。自定义或实验数据集找不到兼容基线时只执行绝对阈值，CI 则始终使用仓库中的批准基线。

## CI 行为

GitHub Actions 在 pytest 之后运行同一个 CLI：

1. 初始化隔离数据库；
2. 导入可公开的企业样例文档；
3. 执行版本化黄金用例；
4. 校验批准基线的数据集版本、指纹和 Top K；
5. 计算绝对阈值与相对基线门禁结论；
6. 上传 `rag-quality-gate-report` JSON 产物；
7. 指标不达标时阻止工作流通过。

报告包含数据集版本、指纹、阈值、失败指标和失败用例，不包含 API Key、真实企业文档或本地数据库。

## 生产边界

当前黄金集用于验证仓库内置检索链路，规模较小，不能代替真实业务验收。生产环境应扩展分领域数据集，按用户权限和问题类型分层统计，并增加人工标注一致性、模型版本、Prompt 版本、延迟和成本门禁。
