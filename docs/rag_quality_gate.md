# RAG 质量门禁

项目使用版本化黄金数据集和确定性离线执行器，在提交阶段检查检索、回答、引用和安全质量。CLI、API、评测中心、Markdown 与 CSV 导出共用同一套计算逻辑。

## 运行方式

从项目根目录运行完整验收：

```powershell
.\scripts\verify_project.ps1
```

只运行批准基线门禁：

```powershell
cd backend
python -m app.eval_gate_cli --output ..\.runtime\evaluation-gate-report.json
```

命令使用临时数据库导入 15 份脱敏企业样例资料，不修改开发数据库。默认关闭外部 LLM 和 Embedding，保证本地与 CI 可复现；门禁失败时返回非零退出码。数据集或 Top K 正在有意调整时，可先用 `--no-baseline` 仅执行绝对阈值。

## 黄金数据集

当前数据集是 `backend/evaluation/golden_cases.v3.json`，批准质量基线是 `backend/evaluation/approved_baseline.v3.json`，批准执行快照是 `backend/evaluation/approved_benchmark.v3.json`。v1、v2 文件只作为历史快照保留。

v3 共 50 条用例：42 条可回答任务和 8 条越权、无依据或 Prompt 注入拒答任务。覆盖管理员、技术员工和普通员工，以及 easy、medium、hard 三档难度。能力标签包括：

- 精确事实与多约束回答；
- 多文档聚合、同义改写和一致事实消解；
- 引用溯源与访问控制；
- 知识边界拒答和 Prompt 注入防护。

每条用例包含稳定 `key`、分类、难度、能力标签、执行角色和问题，还可以声明：

- `required_keyword_groups`：每组至少命中一个同义表达，所有组都必须通过；
- `forbidden_keywords`：回答中不得出现的错误或敏感事实；
- `expected_document_groups`：每组允许多个等价来源，所有来源组都必须召回；
- `forbidden_documents`：不得出现在引用中的受限文档；
- `min_citations`：可回答用例的最小引用数；
- `should_answer`：区分应回答和应拒答任务。

应用启动时把黄金集同步到数据库。黄金用例在 API 和界面中只读，自定义用例不改变版本化基线。规范化内容会计算 SHA-256 指纹，只有同指纹且同 Top K 的历史通过运行才可作为自动基线。

## 指标与策略

| 检查 | 默认要求 |
| --- | --- |
| 用例数 | 至少 40 条 |
| Recall@K | 不低于 80% |
| MRR | 不低于 75% |
| 答案正确率 | 不低于 80% |
| 拒答准确率 | 不低于 80% |
| 访问控制准确率 | 必须为 100% |
| 引用忠实度 | 不低于 90% |
| 安全断言准确率 | 必须为 100% |
| 相对基线回退 | 单项不超过 5 个百分点 |

答案正确率要求全部事实组通过，而不是命中一半关键词。引用忠实度检查答案所需事实是否真的存在于返回引用正文。安全断言同时检查禁答词、禁用文档、引用数量和角色 ACL。拒答用例必须不输出引用，避免把近似材料展示成结论依据。

报告还包含答案完整度，以及按难度、分类、能力的分层统计。它们用于诊断但当前不单独阻断门禁。

## 执行证据

每条结果持久化生成模式、模型、Prompt 版本、输入/输出/总 Token、估算成本和耗时。批次记录聚合这些字段，并通过 API、前端、Markdown 和 CSV 导出。

本地抽取模式的 Token 是估算值；接入供应商时优先使用供应商返回用量。成本只有配置 `LLM_INPUT_COST_PER_1K` 和 `LLM_OUTPUT_COST_PER_1K` 后才有业务含义。延迟受机器和负载影响，批准快照只证明测试环境中的一次可复现执行，不是生产 SLA。

## 批准结果

当前 v3 基线来自真实确定性运行：

- 50/50 用例通过；
- Recall@K `1.0`，MRR `0.9544`；
- 答案、拒答、访问控制、引用忠实和安全断言准确率均为 `1.0`；
- 指纹 `8fd2de0c38975e89b315f3d417acab247a36e4964d726be26c3842cd59251a22`。

MRR 保留真实值，不为了展示效果写成 100%。修改数据集、断言或 Top K 时，必须先用 `--no-baseline` 运行、审查失败样本，再提交新的数据集、指纹、批准基线和基准快照。

## CI 行为

GitHub Actions 在 pytest 后执行同一个 CLI：

1. 初始化隔离数据库并应用版本化 Schema；
2. 导入脱敏企业样例文档；
3. 执行 50 条角色化黄金用例；
4. 校验版本、指纹、Top K、绝对阈值和批准基线回退；
5. 上传 `rag-quality-gate-report` JSON 工件；
6. 任一阻断指标不达标时使工作流失败。

报告不包含 API Key、真实企业资料或本地业务数据库。

## 生产边界

50 条基准验证仓库内置样例语料、确定性本地抽取和当前权限链路，不能代表任意企业语料或外部模型的通用准确率。生产环境仍需按部门、岗位、ACL、时间切片和问题类型扩充人工标注集，记录标注一致性，并为线上模型、Prompt、延迟、成本和业务成功率建立独立门禁。
