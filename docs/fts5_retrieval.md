# SQLite FTS5 关键词检索

项目使用 SQLite FTS5 生成关键词候选，避免每次查询都把当前角色可访问的全部知识片段加载到 Python。FTS5 只承担候选召回，SQLite 中的文档、片段、密级和状态仍是事实源；候选回载时会再次校验当前权限，再执行字段加权 BM25、向量融合和本地重排。

## 工作方式

1. 应用启动时创建 `chunk_fts` 虚拟表。首次升级或索引版本变化时，从现有 `documents` 和 `chunks` 重建一次索引。
2. 每个 SQLite 连接注册 `rag_fts_tokens` 函数，复用应用的 jieba 与字符级中文分词结果。
3. 数据库触发器跟踪片段新增、正文修改、片段删除和文档标题修改，因此上传、重索引、删除、种子脚本和测试直接写库都会同步关键词索引。
4. 查询词经过应用分词、去重、数量限制和短语转义后再进入 `MATCH`，不直接拼接用户输入中的 FTS 运算符。
5. FTS5 按标题 30%、正文 70% 的列权重返回有限候选；应用将其与 pgvector 语义候选合并，只回载小集合并重新校验文档状态与访问级别。

## 配置

```dotenv
RAG_LEXICAL_CANDIDATE_LIMIT=200
RAG_VECTOR_CANDIDATE_LIMIT=100
```

两个值都必须是正整数。关键词候选硬上限为 2000，向量候选硬上限为 1000；实际值至少覆盖请求的 `top_k`。检索调试响应会返回：

- `lexical_backend`：正常为 `sqlite_fts5`，降级时为 `full_scan`。
- `lexical_degraded` 与 `lexical_error`：说明 FTS5 是否不可用及公开错误原因。
- `candidate_count` 与 `corpus_count`：用于确认本次实际回载规模，而不是只声称做了索引。

## 权限与一致性

- FTS5 不保存授权结论。候选查询和最终片段回载都关联当前 `documents.access_level` 与 `documents.status`。
- 文档密级或状态变化立即生效，不需要重建关键词索引。
- FTS5 不可用或查询异常时，系统回退到原有全量 BM25 路径并显式标记降级，保证正确性优先。
- 默认 SQLite JSON 向量后端和 pgvector 故障后的本地向量降级仍需要扫描可访问向量；要消除向量全量扫描，应启用 pgvector。

## 验证

自动化测试覆盖中文分词、触发器生命周期、特殊符号输入、实时权限过滤、FTS5 故障降级和候选规模上限。规模回归用例创建 80 个匹配片段并将候选上限设为 25，断言检索只回载 25 个片段，同时保留 80 个语料总量的诊断值。
