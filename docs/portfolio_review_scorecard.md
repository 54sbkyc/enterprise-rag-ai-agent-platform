## AI 应用能力

这个项目的核心价值在于完整覆盖企业知识库 AI 应用链路：

- 文档解析、切分和检索。
- 基于用户权限的知识片段过滤。
- 带引用来源的 RAG 问答。
- 低置信度问题沉淀为知识缺口。
- Agent 工具调用可追踪。
- 问答质量评测和批量报告导出。

面试官会更愿意相信你理解 AI 应用开发，而不是只会把一个聊天接口接到前端。

## 后端工程能力

后端用 FastAPI 承载主要业务接口，覆盖认证、文档管理、问答、Agent、评测、审计和 dashboard。SQLite 适合本地演示，schema 和数据访问逻辑足够支撑项目说明。

可讲重点：

- 权限边界主要放在后端，而不是只靠前端隐藏。
- 问答、Agent 和评测结果可以持久化，便于审计和复盘。
- 测试覆盖了核心接口和行为契约。

## 全栈交付能力

前端不是只有单个输入框，而是围绕真实工作流组织：

- 首页看 AI 运营指标。
- 问答页看回答、引用、轨迹和用量。
- Agent 工作台看工具调用时间线。
- 评测中心看质量指标和报告导出。
- 治理页面看知识缺口、健康体检和审计。

这能证明你有把后端能力交付成可演示产品的意识。

## 安全与权限意识

企业知识库场景最怕越权和不可审计。本项目体现了几类基础安全意识：

- 管理员和普通员工角色隔离。
- 文档密级影响检索范围。
- 12 条角色化黄金用例会验证低权限角色无越权引用。
- Prompt 注入类问题可被拦截。
- 敏感信息可脱敏。
- 管理操作、问答和拦截记录进入审计日志。

这部分在面试中很重要，因为它能把项目从“玩具 demo”拉向企业场景。

## 可观测与成本意识

AI 应用上线后不能只看回答对不对，还要看运行过程和成本。项目中已经包含：

- 每次问答的决策轨迹。
- token 估算和成本估算。
- Agent 运行次数和工具调用次数。
- 最近 Agent 运行记录。

这类设计会让面试官觉得你知道 AI 应用需要运营和排障。

## 测试与交付意识

项目已经有自动化测试和 GitHub 发布治理：

- pytest 覆盖 Agent、权限、安全、分页、评测门禁、黄金集防篡改、前端契约、CI 和发布清单。
- 代码测试之外，CI 还会用隔离数据库运行 RAG 黄金集；AI 指标退化可直接使工作流失败。
- GitHub Actions 自动运行后端测试。
- 独立 pgvector 任务启动真实 PostgreSQL 扩展，验证 HNSW 查询、权限候选过滤、幂等更新和删除。
- 独立容器任务会构建镜像，并验证生产空密码拒绝、UID `10001`、数据库就绪、管理员登录和持久卷重启。
- 发布检查脚本验证必需文件、忽略规则和 Markdown 链接。
- 最终验收报告记录发布标准和生产化边界。

对于实习或初级岗位，这会明显提升工程可信度。

## 生产化成熟度

当前版本已能通过非 root Docker/Compose 在干净机器完成安全单实例复现，适合作品集、面试演示和小规模内部试用。多实例生产环境还需要：

- 将应用内 BM25 迁移为 PostgreSQL 全文检索或独立检索服务，并接入独立 rerank。
- 将 SQLite 业务事实表升级为 PostgreSQL，并加入迁移工具；当前 pgvector 只承担向量投影。
- 将进程内异步 Agent 迁移到外部任务队列，增加租约、跨实例恢复和人工审批。
- 接入真实 SSO、部门级 ACL、日志平台和密钥管理。

这些边界已经在 [production_roadmap.md](production_roadmap.md) 中整理好。面试时主动说明，反而能体现工程判断。

## 综合判断

如果你把这个项目整理后放到 GitHub，并在简历里按 AI 应用开发项目来讲，它的含金量会明显高于普通管理系统、普通 CRUD、单页面聊天 demo。

最推荐的展示顺序：

1. README 第一屏和运行截图。
2. 问答工作台的引用和决策轨迹。
3. Agent 工作台的工具调用时间线。
4. 首页 AI 运营指标。
5. 评测中心和知识缺口。
6. 自动化测试、CI、发布清单和最终验收报告。
